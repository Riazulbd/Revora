ReferenceThe system in one paragraph

Expo SDK 57 / React Native 0.86 with native Firebase, sharing the web product's live database on project ai-fuel-assistant. Screens in src/app, every derived number in src/calculations (pure, tested), Firestore only inside src/repositories. Storage is canonical integers — metres, millilitres, minor currency units — converted to the web's km / litres / taka in exactly one file, src/repositories/wire.ts. Nothing derived is stored; mileage, odometer, maintenance status and the ledger are recomputed on every read, which is why editing an old record corrects everything downstream.

ChronologicalProblem log

Symptom → cause → fix. Chips: FIXED shipped · OWNER needs an action only the account owner can take.

01

Jest refused to run

FIXED
Symptom

“The React Native Jest preset that jest-expo relies on has moved to a separate package”, then Could not locate module react-native/setup-env.

Cause

jest-expo on SDK 57 peer-depends on @react-native/jest-preset; npm resolved one that didn't match RN 0.86.3. Jest 30 was also ahead of the expected ~29.7.

Fix

Pin @react-native/jest-preset@0.86.3 — always the exact RN version — plus jest@~29.7.0, babel-preset-expo@~57.0.0.

02

ESLint 10 crash

FIXED
Symptom

contextOrFilename.getFilename is not a function from eslint-plugin-react.

Fix

eslint-config-expo isn't ESLint-10-ready — pin eslint@^9.36.0.

03

TypeScript 6 deprecated baseUrl

FIXED
Fix

Drop baseUrl; alias with "paths": {"@/*": ["./src/*"]} — the leading ./ matters.

04

Custom role prop fought React Native's

FIXED
Cause

RN's TextProps has its own accessibility role; the intersection narrowed our type-scale roles to "figure" | "button" | "link" everywhere.

Fix

Omit<RNTextProps, 'role'> in the Txt primitive.

05

Gauge arc: no pathLength in react-native-svg

FIXED
Fix

The design's arc is a half-circle of r = 90, so dash against its true length: Math.PI * 90.

06

Hydration effects in nine editor forms

FIXED
Symptom

React 19 lint errors — “Calling setState synchronously within an effect” — plus a visible flash of empty form before values arrived.

Fix

House pattern now: a route that waits for data, and a form keyed on the record id (<Form key={existing?.id ?? 'new'}>) whose useState initialisers read the record directly. Zero hydration effects remain. Reference implementation: src/app/fuel/add.tsx.

07

Ref reads during render

FIXED
Fix

useStableId became useState(factory) — the lazy initialiser runs exactly once, which is precisely the idempotent-id guarantee. useRecordMutation returns an explicit {submit, isPending, isError, error} instead of mutating the mutation object.

08

Two real bugs in the live-query layer

FIXED
Bug A

A listener that errored synchronously leaked — cleanup ran before the registry entry existed. Register the entry before subscribing.

Bug B

Pull-to-refresh resolved the listener's first snapshot (an already-settled promise), not current data. Cache latest on the entry; refresh now issues getDocsFromServer so it genuinely bypasses the cache — and rejects offline instead of spinning forever.

09

Release build: “Keystore file not found”

FIXED
Cause

The keystore lived under android/app/ — and expo prebuild --clean deletes android/ wholesale.

Fix

Keystore at credentials/revora-release.keystore (gitignored), wired by plugins/withReleaseSigning.js with an absolute path. Rule: nothing precious lives under android/ — it is generated output.

10

The APK was 112 MB

FIXED
Cause

Four ABIs including emulator-only x86, plus eight installed-but-unused dependencies.

Fix

Build with -PreactNativeArchitectures=arm64-v8a,armeabi-v7a; remove the dead deps; R8 on. 112 → 58 MB.

11

Dev-menu permission in the release manifest

FIXED
Fix

SYSTEM_ALERT_WINDOW (React Native's dev overlay) blocked via android.blockedPermissions — Play flags it otherwise.

12

The big one — production sign-up denied every write

FIXED
Symptom

“You don't have access to this record” the moment a rider signed up.

Cause

The app was built against users/{uid}/fuel/… subcollections. The Firebase project already runs the web product's “Moto Companion” ruleset: flat top-level collections (bikes, fuelEntries, fuelAdjustments, odometerEntries, maintenanceRules, services, parts, accessories, expenses, reminders, users, entitlements) keyed by a userId field, field-validated, userId/createdAt frozen after create, and default-deny for anything unlisted. The live database already held real data.

Fix

Rewrote the repository layer to the live schema. wire.ts is the single unit boundary (km↔metres, litres↔ml, major↔minor). Fuel adjustments became dated timeline records with signed litres — a better model, netted into whichever full-to-full interval their date falls in. bikes.currentOdometer is written back on every save while the app keeps deriving it. All writes merge; updates never send the frozen fields; web-only fields survive. Proof: tests/signup-sequence.test.ts replays every serialised write against the downloaded production ruleset in the emulator.

Rule for next time: before writing one repository line against an existing backend, download the live rules — GET firebaserules.googleapis.com/v1/projects/<p>/releases, then GET /v1/<rulesetName> for the source.
13

The project had zero composite indexes

FIXED
Fix

Queries shaped where(userId) + where(bikeId) + orderBy(…) need composites. Fourteen created additively via the REST API — never deploy --only firestore:indexes against a shared project, it may offer to delete unlisted ones. firestore.indexes.json is the inventory.

14

Four design screens had no rules at all

FIXED
Cause

Document vault, Warranties, Safety log and Fast Capture don't exist in the web schema — and the ruleset default-denies.

Fix

Additive rules block in the house style for documents / warranties / safetyChecks / captures. Deployed only after: diff vs live showed 0 deletions, the isolation matrix passed in the emulator, and the owner approved. Prior ruleset backed up first.

15

Toolchain bootstrap from a bare machine

FIXED
Gotchas

brew install --cask temurin@17 needs sudo and fails headless; the formula openjdk@17 doesn't. Two JAVA_HOMEs: gradle wants 17, firebase-tools requires 21. No AVD existed: cmdline-tools zip → sdkmanager "system-images;android-35;google_apis;arm64-v8a" → headless boot with -no-window -gpu swiftshader_indirect. Maestro drives the app through the testIDs already on every control. Emulators automatically get AdMob test ads, keeping automation inside policy.

16

Sign-up said email-already-in-use

FIXED
Cause

The auth user was created during the owner's earlier on-phone attempt — auth had succeeded, only Firestore had failed.

Fix

Test flows sign in instead. The account's records now hold the imported CSV history.

17

AdMob broke the Kotlin build

FIXED
Symptom

Module was compiled with an incompatible version of Kotlin. The binary version of its metadata is 2.3.0, expected version is 2.1.0 — from play-services-ads.

Dead ends

Pin ads SDK 24.6.0 → the RN library needs 25.x APIs. Pin 25.3.0 → same 2.3 metadata. Set android.kotlinVersion → ignored; RN's gradle plugin substitutes the classpath version.

Fix

Kotlin 2.2.20 (a compiler reads metadata one minor ahead) forced on the buildscript classpath by plugins/withKotlin22.js. Remove when RN's toolchain reaches Kotlin 2.3.

18

Play Console showed three release errors at once

FIXED
Cause

One cause behind all three messages: the release contained no new versionCode.

Fix

Every upload increments android.versionCode in app.config.ts — v1.1 is versionCode 2, same signing key, accepted as an upgrade.

19

Advertising-ID warning

FIXED
Fix

AD_ID permission is auto-merged by the ads SDK (verify with aapt2 dump badging … | grep AD_ID). The console half: App content → Advertising ID → Yes → purpose “Advertising or marketing”.

20

“The file is no longer available” on photos

OWNER
Cause

Firebase Storage was never set up — the bucket doesn't exist, and the provisioning API refuses non-console credentials.

Fix

App side (shipped in v1.1): uploadImageOrKeepLocal() keeps every photo on-device when upload fails; the record always saves; the toast says so plainly. Project side, owner-only: Firebase console → Storage → Get started, then firebase deploy --only storage — the rules are already written.

21

Google Sign-In — working, with one future trap

OWNER
Fix

Registered the release keystore's SHA-1/256 on the Firebase Android app via API; webClientId is the client_type: 3 entry in google-services.json.

Trap

Enrolling Play App Signing re-signs with Google's key — add its SHA-1 to Firebase too, or Google Sign-In breaks only in production.

22

Play data-safety form and listing pages

FIXED
Fix

Hosted on the project's Firebase Hosting: /delete-account and /privacy. Form answers on record: encrypted in transit — yes; account methods — username+password and OAuth only; device/other IDs — collected and shared, purpose Advertising (AdMob).

LessonsWhat worked — keep doing it

  • Pure calculation layer, tests first. All 168 unit tests survived the full schema rewrite with only fixture edits — the arithmetic (335 km ÷ 8 L → “41.9”, BDT 2,400 counted once) never broke.
  • Firestore isolated to src/repositories/. Discovering the real production schema — normally a project-killer — was a contained rewrite. No screen changed.
  • Emulator tests against the downloaded production ruleset before touching production: npm run test:rules.
  • testID on every control from day one made Maestro automation trivial.
  • Ids minted before first save plus in-flight guards: a double-tap cannot create duplicates.
  • Merge-writes only, so the web product's fields survive mobile edits.

OperationsRunbook

JAVA_HOME 17 for gradle, 21 for anything firebase-tools. Both installed via Homebrew formulas.

# Verify — always before building
npm run verify                                  # tsc + eslint(0 warnings) + 168 tests
JAVA_HOME=/opt/homebrew/opt/openjdk@21 npm run test:rules

# Build
export JAVA_HOME=/opt/homebrew/opt/openjdk@17
export ANDROID_HOME="$HOME/Library/Android/sdk"
npx expo prebuild --platform android            # --clean wipes android/; keystore is safe in credentials/
echo "sdk.dir=$HOME/Library/Android/sdk" > android/local.properties
./android/gradlew -p android bundleRelease assembleRelease \
  -PreactNativeArchitectures=arm64-v8a,armeabi-v7a
# outputs: android/app/build/outputs/{bundle,apk}/release/  + mapping/release/mapping.txt

# Emulator + UI flows
"$ANDROID_HOME/emulator/emulator" -avd revora -no-window -no-audio \
  -no-boot-anim -gpu swiftshader_indirect -no-snapshot &
"$ANDROID_HOME/platform-tools/adb" install -r android/app/build/outputs/apk/release/app-release.apk
JAVA_HOME=/opt/homebrew/opt/openjdk@21 PATH="$HOME/.maestro/bin:$PATH" maestro test .maestro/

# Deploy
npx firebase deploy --only firestore:rules --project ai-fuel-assistant
npx firebase deploy --only hosting        --project ai-fuel-assistant
npx firebase deploy --only storage        --project ai-fuel-assistant   # after console Get Started

# Assets
node scripts/generate-assets.js        # launcher icons, splash, dark logo
node scripts/generate-play-assets.js   # Play listing: icon-512, feature graphic, framed screenshots

Release checklist: bump version + versionCode in app.config.ts → verify → prebuild → build → confirm signer SHA-256 e78f5718…f16b unchanged → upload AAB → release note.
